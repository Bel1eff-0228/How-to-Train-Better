# v1.0.0：按这份步骤更新 GitHub

本次分两件事：上传项目文件，更新网页；创建新版 Release，提供新版 PDF 和压缩包。只做其中一件，另一个入口不会自动同步。

## 1. 上传项目文件

打开准备好的发布文件夹中的 `01-上传到仓库`。这里已筛出需要的项目文件，不含聊天记录、缓存和旧版打包目录。

1. 打开 [你的仓库](https://github.com/Bel1eff-0228/How-to-Train-Better)，确认当前分支为 `main`。
2. 点 **Add file → Upload files**。
3. 打开 `01-上传到仓库`，把**里面的文件与文件夹**拖进去，不要把最外层的 `01-上传到仓库` 文件夹拖进去。上传后应看到 `README.md`、`book/...`、`assets/...` 等路径，前面没有多套一层文件夹。
4. 显示隐藏项目，确认 `.gitignore`、`.github/workflows/check.yml` 和 `.github/workflows/pages.yml` 也在。上传同路径的文件会更新原文件。这里不要上传 ZIP，也不要上传整个工作目录。
5. 提交说明填 `发布 v1.0.0：局部减脂合并、器械入门与全文易读优化`。若仍按此前方式直接更新，选 **Commit directly to the main branch**，点 **Commit changes**。如果分支受保护，改选新分支，建立 Pull request，检查通过后再合并。

GitHub 网页一次最多100个文件、每个文件最多25 MiB；本次发布文件夹附清单，上传前可核对数量。若页面提示超限，可分批上传，并等最后一批提交完成再检查最终结果。官方说明：[上传文件](https://docs.github.com/en/repositories/working-with-files/managing-files/adding-a-file-to-a-repository)。

## 2. 确认网页更新

1. 点仓库顶部 **Actions**，找到对应**最后一次提交**的 **Check guide** 和 **Publish reading site**。
2. 等两项都显示绿色。旧提交以前的红色记录不代表这次失败；这次有红色时点进去看失败步骤，不先创建正式发布。
3. 如果没有 `Publish reading site`，先查看 `.github/workflows/pages.yml` 是否已上传；再去 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。回到 Actions，选该工作流后点 **Run workflow**，分支选 `main`。
4. 打开 [在线阅读](https://bel1eff-0228.github.io/How-to-Train-Better/)，刷新后确认显示 `v1.0.0`、100条；分别搜索“瘦大腿”“推胸机”“健身房怎么选”。手机也打开试一次。若仍是旧内容，等部署完成后强制刷新或用无痕窗口核对。

以上工作流名称与触发方式来自本项目随包提供的配置。网站部署完成不会自动创建 Release，也不会替换旧 Release 附件。

## 3. 创建 v1.0.0 下载页

打开 [新建 Release](https://github.com/Bel1eff-0228/How-to-Train-Better/releases/new)，填写：

| 字段 | 填什么 |
| --- | --- |
| Tag | `v1.0.0`，选择创建新标签 |
| Target | `main`，确保已是最后一次绿色检查的提交 |
| Release title | `高性价比健身指南 v1.0.0｜器械入门与易读升级` |
| Release notes | 复制发布文件夹中的 `发布说明.txt` |

把 `02-上传到Release` 中的5个文件全部拖入附件区：

- `HowToTrainBetter.pdf`
- `HowToTrainBetter-v1.0.0-readers.zip`
- `HowToTrainBetter-v1.0.0-skill.zip`
- `HowToTrainBetter-v1.0.0-source.zip`
- `SHA256SUMS-v1.0.0.txt`

等附件全部上传完。作为正式版本发布时不选 **Pre-release**，页面提供 **Set as latest release** 时勾选它，再点 **Publish release**。保留旧版 `v0.9.0` 标签和附件。GitHub 自带的 `Source code` 两项会另外出现，这是正常的。官方说明：[管理 Release](https://docs.github.com/en/repositories/releasing-projects-on-github/managing-releases-in-a-repository)。

## 4. 发布后最后检查

从新 Release 页面重新下载 PDF 和 readers ZIP。PDF首页应显示 v1.0.0；读者包解压后打开 HTML，应可检索100条。旧版网页收藏的第5章第11、12条会合并到第1条；先导出旧阅读备份，再在新离线文件中导入即可。在线和离线的浏览器记录仍分别保存。

若网盘也分享PDF，记得另外上传新版PDF，并核对分享链接；更新GitHub不会同步百度网盘。抖音置顶评论可以写：“指南已更新到 v1.0.0，新增器械使用与选健身房，局部减脂问题已集中整理。”

如更新后发现错误，先修正并发布 v1.0.1，不用同一个标签反复覆盖让下载者无法区分。需要暂时回退网站时，用旧版本文件重新提交；历史 Release 可继续保留下载。

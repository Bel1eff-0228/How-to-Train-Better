# TrainBetter AI v2.1：代码审计、研究与实施方案

日期：2026-11-04。阶段：研究与方案，尚未实现 v2.1。

## 1. 审计边界与结论

检查当前 F:/How-to-Train-Better 工作区，基线分支 v2/render-test，最近本地提交 9a97e92。工作区另有既存修改及未跟踪文件；本次不清理、不覆盖、不提交这些文件，不改 main、不推送、不操作 Render。正式编码应从核对过的基线建立独立 v2.1 分支，并只提交明确属于新版本的文件。

核心问题不是模型没有理解“进阶”，而是模型可用空间过窄，且程序在输出阶段把处方统一化。应保留已有 Next.js 应用、模型适配、认证与 API，增加独立的训练编排模块，不重建项目。

本轮实际执行 apps/web 下 npm test：25/25 通过。包含模型替身和故障模拟，不能代表真实模型、真实训练效果或真实 iPhone 验收。本轮没有调用付费模型，没有重新生产构建，也没有进行手机实机测试。

## 2. 当前代码差距

| 文件/范围 | 实际发现 | 影响 |
|---|---|---|
| apps/web/lib/agent/tools.ts | 仅9个动作，健身房/哑铃/徒手各3个，按环境严格相等过滤 | 健身房也不能选择库内哑铃动作；没有垂直拉、肩部与手臂专项等覆盖 |

## 4. 科学证据与不能越过的边界

### ACSM 2026

主题为健康成年人肌功能、肌肥大与体能的抗阻训练处方综述立场文件。论文记录：https://pubmed.ncbi.nlm.nih.gov/41843416/ 。本次未完成论文全文审读，以下依据实际读到的ACSM官方单页摘要：https://www.acsm.org/wp-content/uploads/2026/03/Resistance-Training-Position-Stand-infographic.pdf 。

官方摘要强调主要肌群每周至少2天、逐步增加；力量目标偏较高负荷，肌肥大重视较高周训练量（摘要举约10组/肌群）；普通健康成年人不必依赖每组力竭或复杂周期化。这不能直接变成每个人固定10组的硬规则，也不能给没有测试过1RM的新手假造负重。具体进阶人群、RIR范围和周量上限需要补充证据审读与专业复核。

### 2024分化与全身训练系统综述

Ramos-Campo等，JSCR 38(7):1330–1340，DOI 10.1519/JSC.0000000000004774。读到PubMed摘要与书目信息，未审读全文：https://pubmed.ncbi.nlm.nih.gov/38595233/?format=pubmed 。摘要纳入14项研究、392人；训练量相当时，未发现分化与全身在力量、肌肥大结果上的显著差异。因此应根据时间、偏好和可执行性选择，不能宣称五分化更高级或更科学，也不能把无显著差异说成所有情况下完全等效。

### 对本项目的设计推断

- 4天进阶胸优先，可用上/下肢A/B，让两个上肢日承担不同胸部重点；这是候选设计，不是论文指定处方。
- 2天时全身合理；4→2必须重排全周覆盖与组数，而不是截取前两天。
- 减脂与增肌可共享核心动作。目标差异主要体现在恢复条件、训练量调整策略、额外活动和饮食方向，不用随机换动作制造差异。上述两篇不能单独支持精确减脂热量或所有减脂者统一降量。
- 肌群间接参与不能简单重复计数。首版分别显示直接组和间接参与组，实际总组只计一次；不把固定0.5折算宣称为已证实的生理等价。
- “计划周量”与“已完成训练量”严格区分，无训练日志时不绘制进步或恢复百分比。

## 5. 拟开发的最小编排架构

流程：输入Schema → 风险检查 → AI解析变更意图（仅允许已定义字段）→ 合并旧条件 → 规则选择分化 → 固定种子/稳定排序选动作 → 分配正式组与热身 → 计算周量和时间 → 硬约束校验/软目标解释 → AI解释经过验证的计划 → 返回签名计划。

AI不再决定任意动作名或覆盖程序计算值。解释失败不得伪称AI完成；可明确提供规则计划及解释服务状态，是否采用该降级方式需在实现时确定产品行为。

数据：
- Profile扩展目标、经验、器械清单、分化偏好、重点肌群、排除动作；对旧字段有显式映射。
- Exercise使用稳定ID，主/次肌群、运动模式、器械需求集合、难度、单侧标志、计次/计时类型、替代ID与说明。
- Plan独立schemaVersion、修订version、split、workSets、warmupSets、repRange/duration、restSeconds、RIR、estimatedMinutes、muscleVolume、activityGuidance、progression、decisionSources。
- 训练量区间为可配置的编辑策略，分别记录依据和适用条件；无解返回原因和可调整条件，不能静默突破时间、器械或风险约束。
- 时间按每动作执行时长（含单侧）、组间休息、热身、转场累计；避免把热身组算成正式周量。
- 分化偏好与天数冲突时说明折中，不把自动推荐当医学结论。四分化/五日专项需要定义其具体肌群分配与频率，不能仅有名称。
- 无表现记录时只能提供条件式双重渐进说明；不能自动声称下周应加具体公斤。

## 7. UI方案

首页减少装饰球体与倾斜玻璃卡，保留品牌色、清晰主按钮和真实能力说明。表单基础条件先填，分化/重点肌群按需展开。结果先显示一周肌群安排、分化理由和预计时长，再展开当天动作。

手机使用动作卡：动作名 → 热身/正式组 → 次数或时间 → RIR → 休息 → 合法替代；桌面可使用表格。肌群概览用清晰标签和条形图，标明“计划直接组”“间接参与”，不依赖颜色单独传意。加载、超时、供应商故障区分提示，保留已生成计划。

所有交互箭头/加号/加载符号统一SVG；safe-area需配合viewport-fit测试，不仅添加CSS。真实iPhone Safari必须记录设备、iOS版本、横竖屏、安全区、输入键盘和页面滚动，模拟WebKit不能代替实机通过。

## 8. 验收与部署边界

- A：进阶增肌4×60健身房胸优先，有明确分化、胸优先分配、完整其他肌群覆盖、RIR/休息及可执行时间，不能四天复制三动作。
- B：新手3×45仅哑铃，不出现未经确认的长凳、拉力器等；复杂度与经验匹配。
- C：成对比较相同条件的增肌/减脂，核心动作可相同，但活动、恢复调整、营养方向与理由有可验证差异；不能只改标题。
- D：4→2重新计算分化、频率、周量、时间；无关条件和旧计划保留。
- E：覆盖所有目标、经验、天数、时长和环境组合，以及器械缺项、优先肌群冲突、疼痛、成人年龄、否定病史、提示注入、未知ID、单侧时间、token上限。
- F：桌面/移动自动布局检查与真实iPhone Safari分别验收；目前均未对v2.1执行。
- G：现有25项测试持续通过；补充旧计划迁移、Basic Auth、Origin、签名、限流、供应商503和超时回归。另对真实模型做限额生成/修改，不用替身冒充。

开发使用独立v2.1分支，保护当前Render绑定的v2/render-test。先本地验证，再经用户授权建立隔离测试部署；仍为单实例，独立APP_ORIGIN和访问保护，密钥仅服务端配置。不直接覆盖当前在线版本；回退采用部署已知旧提交，避免改写历史。

结论：可以进入分阶段开发；不能宣称v2.1已完成或通过专业编排/手机验收。第一优先级是动作与计划数据模型、可测试编排，而不是继续润色提示词。

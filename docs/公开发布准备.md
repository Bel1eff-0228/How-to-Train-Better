# v0.9.0 GitHub 发布准备

本文件供维护者使用，读者页面不显示内部测试过程。当前为发布候选；本轮问答与交付检查的实际状态见 v0.9发布检查.md。本轮只准备本地交付，尚未创建远程仓库或公开发布。

## 交付文件，各有用途

- 读者文件：`dist/HowToTrainBetter.html`，双击即可阅读、搜索、收藏；补剂对照和进阶目录可离线使用。
- 读者ZIP／静态网站目录：以 `dist/public-release.json` 指定的包为准，包含8个文件（含正式PDF）。不得把开发服务器开放到公网。
- GitHub源代码包与独立技能包：以 `dist/source-release.json` 指定的两个ZIP为准。源包保留可构建代码、正文、许可、贡献说明和合成题集，不包含原始答卷、执行轨迹、缓存和本机截图。技能包内含由 book/ 生成的 references，不能只拿 SKILL.md。

内部完整快照不等于公开源包，不能直接整目录上传。生成副本都带文件清单与SHA-256，这用于检查内容一致性，不是数字签名或权属证明。

## 构建与检查

需要 Node.js 20及以上、Python 3.9及以上；页面和正文构建无第三方依赖。当前GitHub检查配置使用Node 24。

```text
node tools/build.mjs
node --test tests/*.test.mjs
node tools/qa-browser.mjs
python -m pip install -r tools/requirements-pdf.txt
python tools/build_pdf.py
python tools/package_release.py
node tools/qa-public.mjs
python tools/package_source.py
```

PDF构建与目视检查详见 PDF构建说明.md。浏览器检查另需已有Playwright与Edge；普通使用不需要这些工具。`.github/workflows/check.yml`会在推送或拉取请求时构建、执行一致性测试和打包，不自动发布网站。它不运行模型问答或浏览器测试，不能据CI绿灯宣称医学审核通过。

流程参考 [GitHub官方Node检查文档](https://docs.github.com/en/actions/tutorials/build-and-test-code/nodejs)。云端执行还需首次推送后验证，本地检查不能代替GitHub运行结果。

## 准备上传时

1. 确认实际账户、仓库名称和公开可见性；当前未预填网址。
2. 解压清单指定的source包到新的工作目录，在这个干净副本建立Git仓库。不要从含缓存和历史会话的维护目录直接全量上传。
3. 检查待提交文件与许可、说明，完成初次提交并推送。发布版本暂按v0.9.0；架构路线V0–V8不是产品版本号。
4. 在GitHub查看首次检查结果，再创建对应标签和Release；附上readers、PDF和skill包及校验值。
5. 若同时发布网页，只部署读者目录里的八个文件。核对实际HTTPS网址、下载链接、手机显示及托管日志政策，再把真实地址写回项目。

这里列出的是待执行步骤，没有宣称已建仓库、提交、创建Release或部署。现有Git可用，但本轮未创建Git历史。部署GitHub Pages需另行选择实际仓库设置，参考 [官方自定义流程说明](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)。

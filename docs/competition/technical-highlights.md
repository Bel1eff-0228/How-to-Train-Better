# 技术方案与边界

创建：输入Schema/成年确认 → 风险与明显注入检查 → 检索完整指南条目 → 器械动作筛选 → 服务端模型 → Draft Schema → 业务校验 → 签名计划。
修改：验证签名/有效期 → 检查风险 → 模型提取patch → 合并原条件 → 带原计划重新生成 → 校验新版本。

工具：retrieve_fitness_knowledge、select_exercises、build_training_plan、validate_training_plan、revise_training_plan、estimate_budget_options。详见apps/web/AGENT.md。

知识来自book的100条，含文件路径、章条、来源、核验日期。C级、争议和超一年核验分别标记。没有重新核验全部外部文献；来源ID存在不等于模型解释符合文献。

模型只返回受约束ID，不直接输出任意HTML、购买链接或医疗文本。API Key仅服务端环境变量。请求体40KB、模型输入字符上限、输出token上限、20秒超时、5xx最多重试一次。计划签名防篡改但不加密，不等于用户身份验证。

已增加明显注入语句拦截；仍不是完备注入防护。规则和模型风险判断均可能漏检。全局限流与调用预算仅进程内有效，重启清空；缺少持久账本、单用户公平限流与分布式锁。不能宣传为已具备生产级风控。

动作目录每类器械仅3个动作，实际个性化能力有限；目标/经验未充分改变负荷。预算工具只保证无额外购买，不提供价格优化。复杂修改的条件保留仍依赖模型提取正确性。

## 1. 30分钟冲突复核

原16项全部属于力量目标、2或3天、30分钟、胸优先，跨4种经验和两种器械条件。并非16个都在生理或器械上不可行：旧算法把额外胸部动作当作必选，且单侧动作在最低1组时不再寻找替代。

最小修复：先减少正式组；若仍超时，移除不影响当日主肌群覆盖的重复动作；再尝试同运动模式、器械/经验合法且不损失肌群覆盖的省时替代。单侧计双边、5分钟一般热身、轻量热身和休息下限均保留。输出具体调整警告，不承诺短时计划仍有额外强化量。

原16项已全部通过；原800组矩阵现为800成功、0冲突。不是所有任意条件都可行：缺少拉类设备、排除全部背部动作、2天要求四分化等仍明确拒绝。真正TIME_CONFLICT返回估算最低分钟数及增加时长/调整分化/确认更多器械选项，不自动改变输入。

## 2. 新旧执行流程

旧：Profile → 固定含“全身”的检索 → 模型选旧9动作中的3个 → 统一组次构建 → 校验 → 签名。

新生成：输入版本校验与风险筛查 → 规范Profile → 50动作规则编排 → 完整校验 → 按实际目标与分化检索完整指南条目 → AI选择相关解释与来源 → 严格Schema/来源ID校验 → 再校验计划 → 签名。

新修改：验证签名和有效期 → 读取旧条件 → AI输出局部patch和逐字段原文依据 → 验证字段值、原文、变更意图 → 合并未改变条件 → 全周重排/校验 → 检索新方案知识与解释 → 签名。4→2不是截断原数组；器械与重点修改也重新计算。

AI响应不得包含动作、训练日、组数等计算字段；解释阶段仅允许选择服务器已有决策ID及关联检索来源，解释正文来自通过校验的规则结论。这样不会让自由生成的文字覆盖处方。不是无限制自由聊天，解释的表达丰富度暂时有限。来源支持一般原则，不声称支持精确个人剂量。

修复了Zod部分字段解析的默认值问题：过去partial可能补入auto、空重点肌群、预算0等默认值。现在patch仅保留实际输入的键，并逐个核对原文依据，避免未指定条件漂移。

## 3. API兼容与安全

路径继续为POST /api/plan/create、POST /api/plan/revise。

旧客户端请求不传apiVersion，原中文Profile仍接受；响应保持原days/exercises/sets/reps/rest、mode、profile、reasons、sources、changes、token结构，额外附trainingPlan。虽然外层兼容，内部新生成计划全部由2.1规则引擎生成，未调用旧9动作构建函数。

新版创建示例（不含任何凭据）：

```json
{
  "apiVersion": "2.1",
  "adultConfirmed": true,
  "profile": {
    "goal": "hypertrophy",
    "experience": "advanced",
    "days": 4,
    "minutes": 60,
    "environment": "gym",
    "availableEquipment": ["dumbbells", "bench", "cable", "leg-press", "leg-curl", "chest-press", "lat-pulldown"],
    "split": "auto",
    "priorityMuscles": ["chest"],
    "budget": 0,
    "notes": ""
  }
}
```

新版响应为规范Plan加sources、explanations、token。mode为rules，表示处方由规则计算，AI参与意图和解释。修改仍提交token与message，可选apiVersion；不填写时继承签名中的版本，历史无版本token使用旧响应格式。

旧签名payload（plan/expires）仍可验证，修改时迁移并重建，保留原始输入条件。旧计划没有可靠热身或RIR，不能把旧数据假装转换成已计算的新处方。纯规则readPlan兼容工具与Agent富化读取各有边界：API使用contract.ts里的解析器处理sources/explanations。

旧版健身房只有环境名，没有器械清单：API迁移沿用旧系统已有的腿举、推胸、绳索三类预设并附警告，不擅自新增哑铃或训练凳。新版必须传实际器械。独立upgradeProfile工具仍要求显式确认健身房清单。旧徒手条件若无法实现背部覆盖会明确报错，而不继续旧版忽略背部的成功结果。

保留Basic Auth、APP_ORIGIN、原签名密钥与24小时过期、进程限流、并发保护、供应商有限重试和日额度。签名格式新增严格两段和十六进制检查，拒绝追加段。签名后的旧状态执行Schema检查，不再直接类型断言。

大小上限保持：请求40,000字节、token35,000字符、模型payload50,000字符；签发前新增token上限检查。模型只收到日摘要与相关5条完整知识，不发送整套50动作或整个旧计划。

本地六天90分钟、胸背双重点、全部6项解释和5项来源的样例：模型上下文7,107字符，token18,357字符，修改请求18,392字节。此为实测样例而非对所有未来知识库的大小保证；超限明确报错。六天签名往返在API自动测试中通过。

## 6. 剩余边界与结论

1. 自然语言采用有限词表和逐字段原文验证，复杂、否定或含糊表述可能拒绝，需要明确重述；不是万能意图理解。
2. 非空自由文本限制暂不进入规则编排，疼痛/疾病先拒绝，其他未评估限制也明确返回；不会静默丢掉备注。原宽泛风险词仍可能误拦截，如否认病史。英文大小写风险已归一化。
3. 四分化显式偏好改2天仍需用户同时改auto或全身；自动偏好则自动重排。
4. AI关联来源的细粒度语义仍需要人工复核；输出数值由规则控制，未添加新运动科学结论。
5. 进程限流随重启重置，不是账单级硬上限，继续仅限单实例受控测试。
6. UI暂未重设计，旧卡片可显示新计划但仍有旧布局与符号；未完成iPhone新版验收，不构成公开发布Go。

结论：具备进入UI改版阶段的工程条件，待用户验收。本轮暂停，不自动开始UI或部署。
